How this got to prod

main had not moved since #189 on 2026-08-02. Everything since — 0.6.0, plus the fixes the 2026-08-20 staging smoke test found necessary — was still sitting on staging.

A 2026-08-21 re-verification of the six bugfixes staging had already absorbed found two of them reproducing under different conditions: #374's collision case and #376's row-count logic, filed as #384 and #385. Both were fixed and promoted to staging first. Only once that was clean did staging — 246 commits ahead of main's prior tip — go into a PR and get merged. Nothing about this promotion was a silent fast-forward.

No new defect surfaced

That's a narrower claim than "correct at scale." This run loaded one directory once, in three sequential passes, with no concurrency and no retry. It says the specific defects staging found stay fixed at 20x the row count — not that scale carries no risk of its own.

A follow-up, not a defect

Source files were never archived

All nine files remain at their original upload path under migration/, modification timestamps unchanged, rather than moving to processed/{date}/ the way fs/archival.py is documented to move them — and the way the staging run observed its own files move. Correctness wasn't affected: every audit row reports success and every count reconciles. But a second run against this path would try to re-read all nine files as new, since discovery only skips processed/ and quarantine_files/ and never checked whether either exists here.

Scope and limits

Prod only. No GRANT, REVOKE, DROP or VACUUM was run by an agent — the GRANT SELECT ON SCHEMA needed to verify this run was requested and applied by Yash directly, since no human had queried ingredion_prd before this run.

Not covered:

  • The 26-case edge-case matrix — exercised twice on staging already; this run's ask was volume, not a second correctness pass.
  • Merge writes, and a live re-check of #376/#385 against this run's own data.
  • Streaming and Auto Loader.
  • XML, which approved_formats() still refuses pending #336 and #337.
  • Retry under real transient failure, and why archival didn't run here.
  • Unity Catalog tag application — the prod job configures no tags.
  • ai_metadata_prd and bronze_maintenance_prd, neither run. Maintenance stays paused pending Tier 2 approval — it runs VACUUM.
  • Concurrency and sustained load — three sequential passes over one directory, not a traffic pattern.

State left behind

ingredion_prd now holds 9 bronze tables, _ingestion_audit (9 rows, all success), and _schema_registry (9 rows, one per table). Every table carries CDF at the default 30-day retention. This is the schema's first data — nothing was dropped or overwritten.

All nine source files sit unarchived at /Volumes/.../PROD/Raw/migration/. Clearing or archiving that folder by hand is worth doing before anything else runs against this volume.
